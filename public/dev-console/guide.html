Emergency Console Guide

Lucy Garden — Standalone Dev Console Documentation

Back to Console
1 What is this?

This is an emergency backup console that works independently of the main React app. If the main app at lucygarden.in crashes completely, this console still works because it uses pure HTML + vanilla JavaScript + Firebase CDN.

Access URLs
EnvironmentURL
Productionhttps://lucygarden.in/dev-console/
Localhosthttp://localhost:3000/dev-console/

PIN: 0000 (default) — stored in Firebase settings/devAccess document.

2 When to Use
  1. Main app crashed — white screen, won't load at all
  2. Need to block retailers — critical bug, turn on maintenance
  3. User locked out — unblock or force logout from here
  4. Feature breaking app — disable feature flag immediately
  5. Emergency backup — save data before attempting fix
Important

For regular daily work, use the React Dev Console at /dev. This emergency console is only for when the main app is down.

3 Health Check Tab

First thing to check when something feels wrong.

  1. Opens automatically on login
  2. Response time — green (<200ms) = good, red (>500ms) = Firebase slow
  3. Active Errors — number of unresolved crashes
  4. Total Documents — all data in database
  5. Maintenance — ON means retailers are blocked
  6. Collection Status — each collection's document count + health

If Firebase is disconnected, detailed error message + fix steps are shown.

4 Error Logs Tab

View all app crashes with automatic fix suggestions.

  1. Shows unresolved errors sorted by severity
  2. Each error shows: message, timestamp, user, context
  3. Suggested Fix box — automatic solution based on error pattern
  4. Click "Resolve" to mark as fixed (won't show again)
  5. Click "Clear All" to delete all logs (requires confirmation)

5 Sessions Tab

Full session management — device details, force logout, unblock, reset PIN.

  1. Status indicators — Green dot + "ONLINE" badge = active, Gray = inactive, Red = blocked
  2. User info — Name, phone, area, shop, role (Admin badge shown)
  3. Device details — Device type (iPhone/Android/Windows), Browser (Chrome/Firefox/Edge), OS (iOS/Android/macOS)
  4. Session timing — Last login timestamp + "Expires in Xm" for active sessions
  5. Admin multi-device — Shows all active devices separately with individual "End" button for each
  6. "Force Logout" — Terminates all sessions for that user (confirmation required)
  7. "Unblock" — Removes login lockout after 5 wrong PIN attempts
  8. "Reset PIN" — Resets user's PIN to default 1234 (confirmation required)
  9. "Logout All" — Kicks every online user out at once (emergency only)
Common scenarios

"I can't login" → Check if BLOCKED → Unblock
"Forgot PIN" → Reset PIN → Tell them new PIN is 1234
"Someone else using my account" → Force Logout → They'll need to re-login
Admin on multiple devices → See all devices → End specific one if needed

6 Feature Flags Tab

Disable broken features without deploying code.

  1. See all features with ON/OFF toggle
  2. Click toggle → Confirmation popup
  3. Change takes effect immediately for all users
  4. Retailers see change on next page load

Use case: PDF Invoice feature is crashing → Disable "PDF Invoice" flag → App stops crashing → Fix code → Re-enable flag.

7 Backup Tab

Create emergency database snapshot.

  1. Click "Create Emergency Backup Now"
  2. Saves: users, products, settings, retailer_balances, ledger, orders
  3. Success message shows document count
  4. Old backups listed below — can delete if not needed
Always backup before

Bulk price change, DB cleanup, settings change, emergency shutdown, or any major update.

8 Maintenance Tab

Control app access. Block/unblock all retailers.

  1. Toggle Maintenance — ON blocks all retailers, OFF restores access
  2. Clear Banner — removes any active announcement banner
  3. Emergency Shutdown — Maintenance ON + Kill all sessions + Clear banner
  4. Restore Access — Turns OFF maintenance, app goes live

Admin & Developer can still access during maintenance. Only retailers are blocked.

9 FAQ
How does retailer blocking work? ▼
Admin blocks from Retailers page using inline form (reason dropdown + note). Blocked retailer can still login with correct PIN but only sees "Account Suspended" page showing reason + dues. They can access Support page to raise unblock request. Anti-spam prevents duplicate tickets (same category limited to 1 per 24h). Unblock from Retailers page or Sessions.
Dispatch Slip vs Invoice PDF? ▼
Retailer Track page now has 2 different PDFs: Dispatch Slip (blue themed, royal-700) when order is Dispatched — mentions quantities may adjust. Final Invoice (green themed, mint-700) when Delivered — final bill. Two separate functions in TrackOrder.js.
Dashboard donut chart not showing? ▼
The delivery progress donut chart is now always visible — shows 0% empty ring when no orders. If it's missing entirely, check Dashboard.js for the SVG section. Uses pure SVG + Framer Motion, no external chart library.
Report PDF not downloading from admin dashboard? ▼
Previously crashed because stats.monthRevenue was undefined. Fixed — now uses available data (retailers, pending, overdue). If still failing, check browser console for errors in the PDF generation onclick handler.
PIN not working? ▼
Default PIN is 0000. If changed, check Firebase Console → Firestore → settings collection → devAccess document → pin field.
Console won't load at all? ▼
Check internet connection. This console needs Firebase CDN to load (online only). If Firebase itself is down, nothing will work — check status.firebase.google.com.
Difference between this and React Dev Console? ▼
React Dev Console (/dev) has 20+ tools, charts, analytics — full featured. This emergency console has only 6 critical tools. Use React console for daily work, this one only when React app is dead.
Can retailers access this? ▼
No. It's PIN protected. Even if someone finds the URL, they can't get in without the PIN. After 5 wrong attempts, page reloads.
How to change the PIN? ▼
Firebase Console → Firestore → settings collection → devAccess document → change pin field value.
How to reset a retailer's PIN? ▼
Sessions tab → Find the user → Click "Reset PIN" → Confirm. PIN resets to 1234. Tell the retailer their new PIN.
Backup failed with permission error? ▼
Check Firestore rules — backups collection needs read/write permission. Deploy rules: npx firebase deploy --only firestore:rules
